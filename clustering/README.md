# Clustering

The clustering stage groups concepts that refer to the same real-world entity using shared external URLs: an adjacency list is built from co-occurring URLs, then connected components become clusters, and concept-level edges are projected to cluster-level edges.

| Module | Mode | Notes |
|--------|------|-------|
| [`cluster_concepts.py`](cluster_concepts.py) | `db` | Builds the adjacency list in PostgreSQL, computes the transitive closure, and writes the `clusters` and `cluster_relations` tables |
| [`cluster_graph_concepts.py`](cluster_graph_concepts.py) | `graph` | `AbstractConceptGraphClusterer` — the shared traversal, guard, and projection logic |
| [`cluster_graph_concepts_oxi.py`](cluster_graph_concepts_oxi.py) | `graph` | Pyoxigraph backend (preferred) |
| [`cluster_graph_concepts_rdf.py`](cluster_graph_concepts_rdf.py) | `graph` | RDFLib backend |

The merge is constrained by sense-aware concept identity, the type-coherence merge guard, and the structural self-loop filter. These are described in the [merge-precision refinements](../README.md#merge-precision-refinements) section of the root README.

# Reverse Engineer Clusters

[`reverse_engineer_clusters.py`](reverse_engineer_clusters.py) inspects a clustered ontology database to show where clusters came from, which shared URLs caused concepts to merge, which relations were generated by transitivity, and how those relations trace back to the original source data.

## Usage

### Term lookup

Look up all clusters containing a term:

```bash
python reverse_engineer_clusters.py "come up"
```

Pass a full URI (angle brackets and URL-encoding are handled automatically):

```bash
python reverse_engineer_clusters.py "<https://ofox.co.uk/honk#come%20up>"
```

### Auto-discovery

Scan the database for examples of relations that were coalesced onto a cluster representative via a transitive URL path (i.e. the originating concept had no direct shared URL with the representative):

```bash
python reverse_engineer_clusters.py auto
```

Limit the number of examples shown (default is 5):

```bash
python reverse_engineer_clusters.py auto 10
```

Exclude relations originating from specific sources:

```bash
python reverse_engineer_clusters.py auto 5 WordNet,GeoNames
```

---

## Output

**Term lookup** shows, for each matching cluster:
- All member concepts with their POS and source
- The shared URLs that caused each pair to be grouped
- Any new relations generated by clustering that did not exist directly between the representative concepts, with transitive URL paths shown where applicable

**Auto-discovery** shows examples where a non-representative cluster member contributed a relation to the cluster that the representative did not already have, along with the URL hops connecting that member to the representative.
